## 1. サービス思想・役割分担

当サービスは、各スタジオのWeb予約を乗っ取ったり自動で予約完了まで行うツールではなく、**「都内の複数スタジオを横断し、空き状況と設備を素早く見渡すレーダー」** として位置付けます。

| レイヤー | 役割 |
|---|---|
| **SoundSpot (当アプリ)** | ・渋谷・新宿などエリア内の各スタジオ（ノア、ペンタ等）の空き状況を横断検索<br>・帖数・料金・常設機材（Marshall, JC-120等）での絞り込み<br>・希望する時間帯の「アタリ」を数秒でつける |
| **各スタジオ公式システム** | ・最終的な空き枠の確定・決済・予約完了<br>・当アプリの各部屋カードやタイムラインから「公式で予約 ↗」を押すと、該当スタジオの正規予約画面へダイレクト遷移する |

> **利点**:
> 二重予約や決済トラブルのリスクをゼロにし、利用規約やセキュリティ面でも安全なアグリゲーター構造を維持します。

## 2. スクレイピング＆BAN回避「人間化」ポリシー

ノアなど公式予約システムからデータを取り続けるにあたり、**「相手のサーバーに負荷をかけず、bot判定（IP制限・アカウント凍結）を100%回避する」** ための厳格な運用ルールです。

### ① 完全バックグラウンド定時巡回型（ユーザー連動アクセスは禁止）
- **ユーザーが画面を検索・リロードしても、ノアのサーバーへ直接アクセスさせない。**
- 画面に「🔄 最新に更新」ボタンを設けると、ユーザーの連打やアクセス集中によってノア側から「異常なアクセス頻度（bot）」と見なされてしまうため、**手動更新ボタンは設置しない**。
- サーバーのバックグラウンド処理が「約30分に1回だけ」静かに確認し、結果を手元（DB/キャッシュ）に保存する。ユーザーは何百回見てもその手元のデータを見るだけなので、ノアへのアクセス数は完全に固定される。

### ② 人間らしく見せる「6大ステルス（人間化）ロジック」
機械的・不自然なアクセスログを残さず、スタジオ側のWAFやbot検知システムによるIP/アカウント制限（BAN）を未然に防ぎ、外部サーバーへ無用な負荷をかけないため、`scripts/crawl-studios.ts` に以下の厳格な安全防護ロジックを完全実装・稼働させています。

| No | ロジック名 | 実装仕様・理由 |
|---|---|---|
| **1** | **深夜帯の睡眠（全スタジオ巡回完全停止）** | **日本時間（JST）深夜 01:00 〜 朝 07:30 は、ノアに限らず全スタジオ（ゲートウェイ等含む）の巡回を完全に停止・スリープする。**<br>深夜帯は全スタジオで予約変動がほぼ皆無であり、ログ上も「夜は就寝している自然な人間」を模倣すると同時に、不要な負荷とGitHub Actions実行枠の無駄遣いをゼロにするため。 |
| **2** | **平日昼間の間引き巡回（全スタジオ間引き）** | **月曜〜金曜の 11:00 〜 17:00 は全スタジオ一律で「1時間に1回（毎時00分のみ）」に頻度を抑制（毎時30分枠はスキップ）。**<br>平日の日中は仕事・授業等のため予約変動が極めて緩やかであり、1時間間隔で鮮度として十分。GitHub Actions消費枠を大幅に削減しつつスタジオサーバーへの負荷を最小化。 |
| **3** | **ゆらぎ（Jitter）の付与** | `xx:00:00`, `xx:30:00` のようなキリ番の秒境界で即座にアクセスしない。<br>リクエスト前に **ランダムな待機時間（5〜20秒）** を動的に挿入し、手動ブラウジング特有の不規則なアクセス間隔を再現。 |
| **4** | **ログインセッション（Cookie）の完全再利用** | 定期巡回ごとにID・パスワードをPOSTして再認証を行わない。<br>一度保存したセッション情報（`storageState.json`）をヘッダーに載せてGETリクエストのみで巡回し、ログイン試行の集中による警戒を防止。 |
| **5** | **店舗間の人間的アクセスペーシング** | 複数店舗を巡回する際、ミリ秒単位での同時連打を行わず、**店舗間に3〜6秒のランダム待機時間** を挿入。<br>一括バッチリクエストに見えるスパイクを防ぎ、複数タブを順繰りに眺める人間の閲覧ペースを再現。 |
| **6** | **セーフアボート（即時安全停止）** | 万が一HTTP 401（認証切れ）やHTTP 403（アクセス遮断）を検知した場合は、**即座に処理を中断し再試行（リトライ）を一切行わない**。<br>連続リトライによる更なるアカウントロックやIP恒久ブロックを完全に防止。 |

### ③ GitHub Actions による完全クラウド自動巡回アーキテクチャ（PC不要・サーバーレス運用）
自宅PC（Mac mini等）の常時起動やメンテナンスに頼らず、クラウド上で完結させる自動巡回パイプラインを配備しています。

- **ワークフロー定義**: `.github/workflows/crawl-studios.yml`
- **実行トリガー**:
  - **cron スケジュール**:
    - **基本頻度**: **2時間に1回（偶数時00分）** 起動。
    - **稼働時間**: **日本時間（JST）08:00 〜 24:00**（08:00, 10:00, 12:00, 14:00, 16:00, 18:00, 20:00, 22:00, 24:00 の計9回/日）。
    - **深夜停止**: **全日 01:00 〜 07:30 JST は完全スリープ**（仮想マシン起動なし）。
  - `workflow_dispatch`: GitHub Webコンソールからの手動即時実行（いつでも可能）
- **動作フロー**:
  1. GitHub Actionsランナー（Ubuntu）が起動し、`scripts/crawl-studios.ts` を実行。
  2. **Playwright Chromium完全撤廃 ＆ 純粋Node fetch移行**:
     - Reserve1（ゲートウェイ渋谷、GOODMAN）およびスタジオル（BASS ON TOP）を、重厚なヘッドレスブラウザから軽量・高速な純粋 Node `fetch` ＋ `TextDecoder('euc-jp')` へ完全移行。
     - ヘッドレスブラウザの起動・DOM描画オーバーヘッドをゼロ化し、Chromiumダウンロード時間（35〜45秒）を丸ごと削減。
  3. **スタジオドメイン間並行実行（Parallel Execution）**:
     - Reserve1（渋谷・秋葉原）、スタジオル（秋葉原）、ノア公式APIは、サーバーが完全に独立しているため、`Promise.all` により**並行非同期巡回**を実施。全体のクローリングがわずか **約5〜8秒** で完了。
  4. 取得した最新空き枠（直近14日間分）をSupabaseへ直接一括Upsert同期。
  5. データに差分がある場合のみ、最新JSON（`src/data/`）をリポジトリへ自動コミット＆プッシュ（`[skip ci]` 付与）。
  6. GitHubリポジトリのプッシュを検知してVercelが自動的に最新データで再デプロイし、本番サイトが常時最新化される。

- **クローリング実行分数と月間枠の試算（実測ベース）**:
  - **1回あたりの所要時間内訳**:
    - GitHub Actions起動 ＆ `npm ci`: 約15〜20秒
    - Playwright Chromiumインストール: **0秒（完全削除・不要化）**
    - 並行クローラー実行（`crawl-studios.ts`）: 約5〜8秒
    - Supabase同期 ＆ Gitコミット: 約3〜5秒
    - ➔ **合計 約25〜30秒 / 回**（GitHub Actionsの請求計算は1分未満切り上げで **1分 / 回**）
  - **1日の消費分数**:
    - 9回 / 日 × 1分 = **9 分 / 日**
  - **1ヶ月（30日）の消費分数**:
    - 9分 × 30日 = **約270 分 / 月**
    - ➔ GitHub Actions無料枠（**2,000 分 / 月**）の **わずか13.5%** に収まり、無料枠を9割近く温存した上で2時間ごとの高頻度リアルタイム同期を安全に継続可能。

## 3. キャッシュ運用設計（静的データ vs 動的データ）

スタジオ情報の性質に応じて、保存期間（TTL: Time-To-Live）を2層に分離します。

```mermaid
flowchart TD
    subgraph 静的データ (Static Data)
        A1[部屋名・帖数]
        A2[常設機材: アンプ/ドラム]
        A3[基本料金表 / 個人練習料金]
        A4[住所・電話番号・アクセス]
        A1 & A2 & A3 & A4 -->|半月〜1ヶ月に1回更新| DB1[(静的データベース)]
    end

    subgraph 動的データ (Dynamic Data)
        B1[特定日のカレンダー空き枠]
        B2[◯時〜◯時の予約済みステータス]
        B1 & B2 -->|バックグラウンドで約30分おき更新| DB2[(短期キャッシュ)]
    end
```

| データ種別 | 対象データ | 更新サイクル | 運用方針・保存先 |
|---|---|---|---|
| **静的スペック** | 部屋構成、帖数、アンプ/ドラム型番、基本料金、電話番号 | **半月〜1ヶ月に1回** | 内装工事や機材変更は滅多にないため、頻繁なクローリングは行わない。<br>**Supabase（`studios`, `rooms`, `room_equipments` テーブル）** に永続保持。 |
| **動的空き状況** | 各日付・各時間帯の予約枠（空き / 予約済） | **約30分おき** | 上記の「6大ステルスロジック」に基づき、GitHub Actionsからバックグラウンドで穏やかに更新。<br>**Supabase（`availability_slots` テーブル）** へ直接Upsertし、Next.js APIルート（`/api/studios`）経由でクライアントへ即時配信。 |

> **デモ用ダミーデータの完全排除方針**:
> 初回プロトタイプ検証用に使用していたダミースタジオ（吉祥寺・千葉・柏）および乱数ハッシュによる架空スロット生成ロジックは**完全に撤廃**しました。
> 現在SoundSpotに登録・表示されるスタジオは、都内3大エリア（渋谷 8店舗・新宿 4店舗・秋葉原 4店舗）の**実在する16店舗・169部屋の公式スペックおよび実データ（公式API・公開カレンダー巡回・電話受付）のみ**で純粋に構成されています。

## 4. スタジオ別データ仕様・連携方針

### 4.1 サウンドスタジオノア (NOAH)
- **予約形態**: 完全Web予約システム（会員ログイン必須）。
- **認証仕様**: 会員ID（メールアドレス）＋パスワードによるCookieセッション管理。
- **データ取得先**:
  - 各店舗の部屋マスター: `/noahweb/Chart/studios`
  - 日付ごとのスケジュール枠: `/noahweb/Chart/schedule?store_id=...&date=...`
- **店舗特性（例: 渋谷2号店 全14部屋）**:
  - **00分開始部屋（7部屋）**: A1st, A2st, G1st, G2st, B1st, B2st, E1st
  - **30分開始部屋（7部屋）**: Sst, A3st, G3st, B3st, E2st, Cst, Vo.Booth
  - 1回のアクセスで同日の全部屋の空き状況（`is_booked`, `web_reserve_flg`）を一括取得可能。

### 4.2 スタジオペンタ (PENTA)
- **予約形態**: **電話受付・店頭受付のみ（Web予約システムは全店未導入）**。
  - ※公式サイトは `studiopenta.jp`（旧 `.net` は廃止）。
- **データ管理方針**:
  - **架空の空き枠（ダミーデータ）は完全排除**: ユーザーに「Webで予約できる」と誤認させないため、スロットデータは常に空（`slots: []`）とする。
  - **公式HPからのスペック反映**: 新宿店などの部屋構成（MEDIUM 14帖, LARGE 16帖）、常設機材（JCM2000, JC-120, Ampeg）、料金（通常/昼割/個人練習）を公式HPより正確に反映。
  - **UI表示**:
  - 検索カードに **「電話受付スタジオ: 空き状況・予約はお電話にて」** のアンバーバッジを表示。
  - アクションボタンは「公式で予約 ↗」ではなく、ワンタップで発信可能な **「📞 電話で予約 (`tel:03-3351-3140`)」** ボタンを表示。

### 4.3 ベースオントップ 秋葉原昭和通り口店 (BASS ON TOP)
- **予約形態**: 公開Webカレンダー（スタジオル / shop id: `705`）。
- **認証仕様**: スケジュール・空き枠閲覧は**完全ログイン不要**。
- **データ取得先**:
  - FullCalendar / スタジオル API エンドポイント: `https://studi-ol.com/get_schedule_shop`
  - パラメータ: `shop_id=705&start=YYYY-MM-DD 00:00:00&end=YYYY-MM-DD 23:59:59`
- **予約可能・確認可能期間**:
  - **きっかり3ヶ月先（当日から91日後）まで**（例: 9月5日時点であれば **12月5日まで**）。
  - 12月6日以降（92日目以降）はイベントデータ件数が0件（未開放）となり、システム上毎日日付が変わるタイミングで1日ずつ先の日程が解禁される仕様。
- **店舗特性（全8部屋）**:
  - **00分開始部屋**: 1st (17帖), 2st (9帖), 3st (9帖), 4st (15帖), Piano (3帖)
  - **30分開始部屋**: 5st (15帖), 6st (9帖), 7st (7帖)
  - リアルタイムにバンド予約済み（`pBand`）および個人練習予約（`pInd`）のステータスを取得可能。

- **店舗特性（全7部屋・6帖〜50帖）**:
  - A〜G st（6帖〜15帖）およびMusic Inn（50帖）。毎時00分開始。
  - 公式料金テーブルより平日昼・土日祝料金および個人練習（前日21時受付開始）料金を完全反映。

## 5. UI / タイムライン設計ロジック

### ① 30分開始枠の物理シフト（50%オフセット配置）
ノアなどのスタジオでは、ロビーの混雑緩和のため「00分スタートの部屋」と「30分スタートの部屋」が混在しています。これを文字ラベルだけでなく**視覚的に一目で区別**できるグリッド構造を採用しました。

```
[時間目盛]   |  10:00  |  11:00  |  12:00  |  13:00  |
------------------------------------------------------
00分開始部屋 | [ 10:00-11:00 ] | [ 11:00-12:00 ] | ...
30分開始部屋 | (空白) | [ 10:30-11:30 ] | [ 11:30-12:30 ] ...
               ↑ 半枠(30分)右に物理シフト
```

- **グリッド構成**: 06:00〜24:00（18時間）を **36分割（1時間＝2列）** のCSS Gridで描画。
- **00分開始部屋**: 06:00からそのまま2列幅（`col-span-2`）で配置。
- **30分開始部屋**: 先頭に1列分（30分相当: 06:00〜06:30）の空スペーサーを自動挿入し、以降のスロットを**時間ヘッダーのちょうど中間（50%位置）から物理的にずらして配置**。
- **バッジ配色**:
  - `青`: 通常枠（00分開始）
  - `紫`: 時差枠（:30開始）
  - `黄`: 電話受付スタジオ

### ② 個人練習ルールの取り扱い
- 個人練習は「前日21時受付開始」「1〜2名限定」「特定料金」など各社でルールが大きく異なります。
- バンド予約の空き枠と混同しないよう、料金表示には「バンド通常料金」と「個人練習料金（¥xxx/人/h）」を併記し、詳細モーダルで注意事項を案内します。

### ③ 「1スタジオ ＝ 1親カード ＋ 部屋リスト」集約表示設計（無駄な重複情報の徹底排除）
- **課題**: 以前の「1部屋＝1カード」方式では、同じスタジオ（音楽館やGOODMAN等）のヘッダーやロゴ、住所が何度も縦に並び、さらに全カードに「14:00〜15:00の空き状況」という重複した大きな帯が表示され、画面のスクロール効率と視認性を著しく損なっていた。
- **仕様**:
  - **構造**: **「1スタジオ ＝ 1親カード」** とし、その内部にスタジオ内の各部屋をスリムな行（リスト）で並べる構造に全面リファクタリング。
  - **親カードヘッダー**:
    - スタジオ名、チェーン名、最寄り駅、営業時間（24h等）、価格帯レンジ（¥2,200〜¥10,640/h）、該当時間帯の「空き部屋数（例: 4部屋 空きあり）」を1回だけ表示。
  - **部屋行（スリムリスト）**:
    - 各行に「部屋名」「帖数」「開始分（:00/:30）」「主要アンプ（JC/Marshall）」「料金（¥/h）」「空き/満室アイコン」「詳細開く矢印」を横1行でコンパクトに配置。
  - **重複文言の完全排除**:
    - ユーザーが自ら検索条件で指定している時間帯（例: 14:00〜15:00）を各カードに文言で再掲するのを廃止し、スリムな `[✓ 空き]` / `[✕ 満室]` バッジに集約。
  - **カードフッター**:
    - Web予約スタジオは「公式WEB予約サイトを開く ↗」、電話受付スタジオは「お電話で空き確認・予約 (tel:)」ボタンをカード最下部に1つ配置。
- **効果**:
  - 秋葉原の全36部屋がわずか数枚のスタジオカードに美しく整理され、1画面内で各スタジオの空き部屋・帖数・料金が即座に比較可能となった。

### ④ 満室部屋の表示・非表示トグル設計（空検索時のノイズ除去）
- **課題**: 混雑する日時（土日の昼〜夜など）では大半の部屋が予約済み（満室）となり、予約できないカードをスクロールし続ける必要があり、探している空き部屋を見落としやすい。
- **仕様**:
  - **デフォルト動作**: **「満室の部屋を非表示（空き枠ありのみ表示）」を標準（ON）** とする。
  - **UIトグル**: 検索結果件数の横に `[● 満室を非表示中]` のトグルボタンを常設。ワンクリックで `[● 満室も表示中]` へ切り替え可能。
  - **判定ロジック**: ユーザーが指定した希望時間帯（例: 14:00〜16:00）に重なるスロットのうち、1つも `available` が存在しない部屋を瞬時に除外する。

### ⑤ スタジオ・部屋の自然整列ルール（公式スタジオ順・アルファベット・階数優先）
- **方針**: 00分開始・30分開始での人工的なグループ分割（00分部屋を全室並べた後に30分部屋を並べる等）は行わない。30分開始はタイムラインの視覚的シフト（50%オフセット）で直感把握できるため、部屋順序の優先度からは外す。
- **仕様**:
  - **ソート基準**: 各スタジオ公式の部屋命名規則およびフロア構成に準拠した**自然順序（Natural Order）** を標準とする。
    1. **BASS ON TOP**: `1st, 2st, 3st, 4st, 5st, 6st, 7st, Piano`（部屋番号順）
    2. **STUDIO GOODMAN**: `201st〜205st (2F), 301st〜305st (3F)`（階数・部屋番号順）
    3. **スタジオ音楽館**: `Aスタジオ, Bスタジオ, Cスタジオ, Dスタジオ, Eスタジオ, Gスタジオ, Music Inn`（アルファベット順）
    4. **サウンドスタジオノア**: `A1st, A2st, A3st, B1st, B2st, Cst+Sub, E1st, E2st, G1st, GSst, Booth1`（部屋記号・フロア順）
  - ソートドロップダウンに「スタジオ・部屋順（公式）」を新設し、デフォルトの並び順として採用。空き枠優先や料金順ソート時も、同順位のタイブレークにこの自然順序を適用する。

### ⑥ 早朝・モーニング枠の表示切替（デフォルト9〜24時 & トグル展開）
- **背景**: 一般的なバンド練習需要の大半は午前〜深夜帯（9:00〜24:00）であり、最初から朝6:00を表示すると横幅が冗長になり視認性が下がる。一方で早朝練習・モーニングパック需要も確実に存在する。
- **仕様**:
  - **標準表示**: デフォルトは **09:00 〜 24:00**（15時間 = 30カラム）とし、画面をすっきり整理。
  - **早朝枠トグル**: 検索バーおよびタイムライン上部に `[ ] 🌅 早朝(6〜9時)` のトグルチェックボックス/ボタンを常設。
  - **展開動作**: ONに切り替えると、検索セレクトおよびタイムラインが滑らかに **06:00 〜 24:00**（18時間 = 36カラム）へ即座に展開される。

### ⑦ タイムライン指定枠の強調表示（ハイライト＆自動1時間後連動）
- **仕様**:
  - **1時間後自動設定**: 検索バーの開始時間（例: `14:00`）を選択した際、またはタイムライン上の任意のマスをクリックした際、自動的にその1時間後（`15:00`）が終了時刻としてセットされる。
  - **現在指定枠の視覚的強調**:
    - ユーザーが現在指定している時間帯（例: 14:00〜15:00）の列ヘッダーに `14:00 ◀指定` のエメラルドバッジを表示。
    - 全スタジオの該当コマに **鮮明な発光リング（ring-2 ring-emerald-400）・拡大（scale-[1.03]）・ドットインジケーター** を施し、自分が狙っている枠がタイムライン上で一目で浮き上がって見えるように強調する。
  - **ダイレクト時間選択**: タイムライン上の空きマスをクリックするだけで、その時間が検索バーの時間帯に瞬時に同期される。

### ⑧ 広さ指定チェックボックス（複数選択＆即時絞り込み）
- **背景**: 従来の「10帖以上」「12帖以上」といった単一の下限ドロップダウンでは、「10〜12帖のちょうど良い部屋を探したい」「狭すぎる部屋や広すぎて高額な部屋を除外したい」というバンドマンの実際のニーズに応えられなかった。
- **仕様**:
  - **選択肢**:
    - `〜9帖`: 個人練習・少人数（2〜3人）向け
    - `10〜12帖`: 3〜4人バンド標準
    - `13〜15帖`: 4〜5人バンド・ゆったり
    - `16帖〜`: 大人数・ビッグバンド・ゲネプロ向け
  - **複数選択可能**: 独立したチェックボックスボタングループとし、例えば「10〜12帖」と「13〜15帖」を同時選択して中〜大型部屋のみを一覧化できる。
  - **未選択時の動作**: チェックが0個の場合は「全広さを表示」として動作し、1つ以上選択された時点で該当範囲の部屋のみを即座にフィルタリングする。
  - **クリア機能**: 1つ以上選択されている場合、ラベル横に `[クリア]` ボタンが表示され、ワンタップで全選択解除が可能。


### ⑧ 24時間・長時間営業（深夜・早朝）スタジオの視認性設計

- **仕様**:

    - `✨ 翌朝5時まで (土日朝9時~)`（ベースオントップ）: インディゴバッジ
    - `✨ 予約時24h対応`（音楽館）: インディゴバッジ
    - モーダル内に営業時間サマリーを明記。
  - **タイムライン**:
    - 各行のスタジオ名横に `[24h]` や `[深夜早朝]` のミニバッジを配置し、なぜそのスタジオだけ特定時間帯に枠があるのかを直感的に把握可能。
  - **こだわり条件フィルター**:
    - 機材フィルター群に `✨ 24時間・長時間営業のみ` の絞り込みボタンを追加。ワンクリックで長時間営業スタジオのみを抽出可能。

### ⑨ ツインペダル条件の撤廃（UIのノイズ削減）
- **背景**: 国内のリハーサルスタジオ（ノア、ベースオントップ、スタジオ音楽館、STUDIO GOODMAN等）では、常設ドラムセットへの自前ツインペダルの持ち込み・使用は原則として制限されず、標準で許可されている。
- **仕様変更**:
  - 検索フィルターバーから「ツインペダル使用可能」トグルを完全撤廃。
  - スタジオカードのタグ表示、および部屋詳細モーダルのドラムセット欄から「ツインペダル可否」バッジを削除し、JC-120/Marshall/アンプ型番/レコーディングなど真に差別化される機材情報に絞り込んで表示のノイズを低減。

### ⑩ スマートフォン（モバイル）表示最適化方針（Mobile-First Optimization）
- **背景**: バンドマンがスタジオを探すシチュエーションの多くは外出先や移動中のスマートフォン利用（片手操作・親指タップ）であるため、狭いビューポート（375px〜430px）での視認性と操作性を最優先する。
- **仕様**:
  - **予約種別切り替えタブ**: スマホ画面では `grid-cols-2` による2列等分割レイアウトを採用し、片手でも親指が届きやすく押し間違いのないタップ領域を確保。
  - **機材・こだわりフィルター**: タグ群を折り返して縦長になりすぎないよう、横スクロール（`overflow-x-auto`）＋コンパクトチップ（`py-1.5 px-3 text-xs`）を採用。
  - **スタジオ親カード（集約リスト）**:
    - 店舗名ヘッダーのフォントサイズをスマホ向けにレスポンシブ調整（`text-base sm:text-lg`）。
    - 部屋行（Room Row）は左側に「部屋名・帖数・開始分」、右側に「料金・空きバッジ」をコンパクトに配し、狭小画面でも不自然な改行やはみ出しを防止。
    - 最下部のCTAボタン（「公式WEB予約を開く ↗」/「電話で空き確認・予約」）は、スマホでの押しやすさを重視し **高さ44px（`h-11`）以上の押しやすいタッチターゲット** を確保。
  - **タイムラインのレスポンシブ固定列幅 & 左端完全密着 (`sticky left-0`)**:
    - 1列目（スタジオ名・部屋名固定列）の幅を、PC時は `220px`、スマホ時（`sm` 未満）は **`135px`** に最適化。
    - スマホ幅（375px〜390px）でも、右側のスロット表示・スライド可能領域を約240px〜255px確保し、横スクロール操作を格段に快適化。
    - スクロールコンテナ（`overflow-x-auto`）の左右パディングを排除（`px-0`）し、固定列が左端 0px に1ミリの隙間もなく完全に密着。パディングの隙間からスロットがチラ見えする現象を完全解消。
    - スタジオ見出し行の第1列（スタジオ名）を `sticky left-0 z-30 bg-slate-800 border-r`、各部屋行の第1列（部屋名）を `sticky left-0 z-20 bg-slate-900 border-r` とし、完全不透明なソリッドカラーと適切な z-index 設計により、横スクロール時に右側のスロットや補足情報（駅名・公式リンク）が固定セルの裏に綺麗に潜り込む構造を確立。スタジオ名は最大幅（135px/220px）で自動 `truncate` 処理。
  - **対応スタジオ一覧モーダルのスマホ固定解除・スリム化**:
    - モーダルヘッダー内のサマリーカード（対応エリア、店舗数、部屋数等の4枚のカード）を固定ヘッダーから除外し、スクロール可能エリアの先頭へ移動。
    - スマホ表示時の固定ヘッダー高さを約70px〜90pxに圧縮し、一覧の可視領域を画面の約80%まで大幅拡大。

### ⑪ 対応スタジオ・部屋・常設機材一覧モーダル（SupportedStudiosModal）

  - **サマリー統計（スクロール領域内配置）**:
    - 3大エリア（渋谷 8店舗 / 新宿 4店舗 / 秋葉原 4店舗）
    - 計16スタジオ・169部屋の規模感
    - リアルタイムWeb同期 10店舗 / 電話予約 6店舗
  - **絞り込み・機材検索機能**:
    - エリアタブ切替（すべて 16 / 渋谷 8 / 新宿 4 / 秋葉原 4）

### ⑬ 前後30分枠（±30分）の柔軟マッチング仕様（最大候補数の提案）
- **背景**: 都内のリハーサルスタジオは「毎時00分開始スタジオ（GOODMAN、音楽館等）」と「毎時30分開始スタジオ（ノア、ベースオントップの一部部屋等）」が混在している。ユーザーが例えば「11:00〜12:00」で厳密検索すると、30分開始スタジオの「10:30〜11:30」や「11:30〜12:30」といった空き枠がすべて満室扱いとなり、予約可能な有力候補を見落とす原因となっていた。バンドメンバー間では30分前後の時間調整は容易に行われるため、前後30分の枠も含めて広く空き枠を提案する。
- **仕様**:
  - **判定優先順位**:
    1. **完全一致（Exact）**: 指定時間（例: 11:00〜12:00）に空きがある枠。
    2. **前30分（Early: -30分）**: 30分前（例: 10:30〜11:30）に空きがある枠。
    3. **後30分（Late: +30分）**: 30分後（例: 11:30〜12:30）に空きがある枠。
  - **UI強調表示ルール（カード＆タイムライン共通）**:
    - **完全一致（Exact Match）**: **緑強調表示（Emerald Highlight）**
      - 指定開始時刻と完全に一致する枠（例: 11:00開始指定時の11:00枠、12:30開始指定時の12:30枠）。
      - **スタジオカード**: `[✓ 空き]`（エメラルド背景 `bg-emerald-950`、グリーン枠線 `border-emerald-600`、グリーン文字 `text-emerald-300`）。

    - **前後30分ズレ（±30min Shifted Match）**: **青強調表示（Blue Highlight）**
      - 指定開始時刻から前後に30分ズレた枠（メンバー間での時間調整が容易な候補枠）。

        - 12:00開始枠 ➔ **青強調（前30分ズレ）**

  - **満室除外フィルター（`hideFullyBooked`）**:

### ⑮ カレンダー利用日選択の3週間制限（クローリング同期範囲との整合）
- **背景**: システムがバックグラウンド巡回（GitHub Actions）で実際に取得・保持しているリアルタイム空き枠データは「本日〜3週間先（21日間）」である。カレンダーでそれ以降の日付が自由に選択できてしまうと、データが存在しない未来の日付に対してすべて「未取得」または「満室」と表示され、ユーザーに誤認を与えるUX上の齟齬が発生する。
- **仕様**:
  - **検索バーの日付選択制約**:
    - `<input type="date">` に `min={本日}` および `max={本日 + 21日}` をHTML標準属性として設定。
    - 入力欄直下に `※リアルタイム空き枠同期中: 本日〜3週間先まで` のガイド文を明記。
  - **フロントエンド・状態管理のガード（クランプ処理）**:
    - URLパラメータや直接入力等で範囲外の日付が渡された場合、`HomePage` の状態変更ハンドラ（`handleFiltersChange`）で自動的に `[本日, 本日 + 21日]` の範囲内にクランプ（補正）する。
  - **クイック日付ボタンの適合**:
    - 「今日」「明日」「今週末（土）」「今週末（日）」の各ショートカットボタンは常に7日以内のため、本制約と完全整合。

### ⑯ 未取得（未同期）スロットの明示表示設計（満室・電話受付との3態分離）
- **背景**: 従来の実装では、クローリング未実施の日時や、APIから特定時間帯のデータが取得できていないWebスタジオのスロットについて、判定ロジックが「空き枠なし（`available: false`）」として扱い、結果として `[✕ 満室]` と赤色表示されていた。これにより、実際には空いている可能性があるにもかかわらず「埋まっている」と誤解される問題が生じていた。さらに、予約済みが `-`、未取得が `—` だと視覚的に紛らわしかったため、予約済みを明確に `×` で表現する。
- **仕様（スロットの3態分離）**:
  スタジオおよび各部屋・各時間枠の状態を以下の3つに厳密に分離・定義。
  1. **確定ステータス（データ取得済み）**:
     - `○ 空き`（エメラルド）: クローラーが空き枠を確認済み。
     - `~ 空き`（ブルー）: 前後30分枠に空きを確認済み。
     - `✕ 満室` / `× 予約済`（スレート）: クローラーが予約済みであることを確認済み。
  2. **電話受付専門スタジオ（PENTA等）**:
     - `要TEL` / `TEL`（アンバー）: Web予約非対応のため、電話で確認・予約するスタジオ。
     - スタジオカード下部CTAは「電話で予約 (`tel:`)」を優先表示。
  3. **未取得・未同期（Unfetched）**:
     - `— 未取得` / `— 未同期` / `—`（スレート破線 `border-dashed border-slate-700`、文字 `text-slate-500`）:
       - 当該日時のスロットデータがクローラーにより取得されていないWeb予約スタジオ。
       - ツールチップに「この日時の空き枠データは未取得です。公式WEB予約サイトをご確認ください。」と案内。
       - スタジオカードの全室が未取得の場合は親カードヘッダーにも `[— 未同期]` を表示（満室の赤バッジと明確に区別）。
       - タイムラインビューの該当マスも破線枠 `—` とし、予約済みの `×` と視覚的に完全分離。凡例にも「未取得」を追加。
       - スタジオカード下部CTAは電話ではなく正規の「公式WEB予約を開く ↗」を確実に提供。
  - **満室非表示トグル（`hideFullyBooked`）の挙動**:
    - 「満室を非表示」が有効な場合でも、未取得（`unfetched`）および電話受付（`phone_only`）の部屋は**除外せず表示を維持**し、ユーザーがスタジオの存在を見落とすことを防止。
  - **コンバーター内の日付スライド投影・空き枠捏造フォールバックの完全撤廃**:
    - 初期プロトタイプにおいて、秋葉原（`akiba-converter.ts`）、ゲートウェイ（`gateway-converter.ts`）、ノア（`noah-converter.ts`）で実データ範囲外の日付が指定された場合に過去スロットを日付書き換えで投影したり空き枠を自動生成していた暫定ロジックを完全撤廃。
    - 実データの日付と厳密に一致（`slot.start_time.startsWith(targetDate)`）するスロットのみを抽出し、該当日のデータが存在しない場合は確実に `slots = []`（未取得）として扱い、ユーザーへ虚偽の空き枠を見せないデータ整合性を確立。

#### カテゴリ定義
- **カテゴリA（公開Webカレンダー）**: ログイン不要でカレンダーや枠状況が一般公開されており、最も安全・高速に連携可能（Reserve1, スタジオル等）。
- **カテゴリB（要認証Web予約システム）**: 会員ログインやCookieセッションが必要だが、APIや画面解析で自動取得可能（ノア等）。
- **カテゴリC（電話・店頭のみ）**: Webシステムなし。ダミー枠を廃止し、1スタジオ1カードで電話予約へ誘導（ペンタ等）。
- **カテゴリD（申請型・イベント兼用）**: リアルタイムな空き枠カレンダーがなく、メールやフォームでの折り返し確定。

1. **予約・検索需要の集中ゾーン（直近1〜2週間が全体の8割以上）**:
   - リハーサルスタジオの空き枠検索において、ユーザーが「今すぐ枠を押さえたい」需要の大半は**「今日」「明日」「今週末」「来週」などの直近1〜2週間に集中**しています。
   - 2〜3ヶ月先の枠は「ワンマンやツアーのゲネプロ予約」など公式Webから長期的計画で直接押さえるケースが多く、直前枠ほど頻繁なキャンセル・空き枠変動が発生しません。
2. **相手サーバーへの負荷軽減とBAN回避（人間化ポリシー遵守）**:
   - 全16店舗に対して90日分（3ヶ月分）の全カレンダーを毎時クローリングすると、1回のクローラーで**数千回〜1万回以上のHTTPリクエスト**が発生し、相手サーバーへ多大な負荷をかけ、WAFやbot検知システム（Cloudflare等）によるIP/アカウント制限のリスクが跳ね上がります。
3. **GitHub Actions実行時間と無料枠の維持**:
   - 90日分を巡回すると1回の実行時間が10〜15分に達し、GitHub無料枠（2,000分/月）を瞬時に超過します。
   - したがって、**「予約変動が最も激しい直近1〜3週間」をスライディングウィンドウ（日次更新）で集中的・穏やかに巡回する**設計が、サーバー負荷・コスト・ユーザー利便性のすべてにおいて最も最適なバランスを実現しています。

| パス | 種別 | 役割・概要 |

| `docs/SYSTEM_DESIGN_AND_SPECS.md` | ドキュメント | **本ドキュメント**（設計仕様・運用ルール・エリア調査マップ） |

| `scripts/lib/ongakukan-fetcher.ts` | モジュール | **スタジオ音楽館（ajg.jp）用超軽量スクレイパー**（Node fetch / アキバ店全7部屋・21日間自動パース） |
| `scripts/lib/noah-fetcher.ts` | モジュール | **サウンドスタジオノア用スクレイパー**（公式Schedule API / 秋葉原店全11部屋・21日間自動パース） |
| `src/data/akihabara-real.json` | データ | 秋葉原4スタジオ（BOT、GOODMAN、音楽館、NOAH）全36部屋の100%実データ（機材・料金・リアル空き枠 16,766スロット） |

| `src/data/gateway-shibuya-real.json` | データ | ゲートウェイスタジオ渋谷道玄坂店 全12部屋・21日間の実データ（機材・料金・リアル空き枠 3,528スロット） |
| `src/lib/gateway-converter.ts` | コンバーター | ゲートウェイ渋谷実データJSONをアプリ共通の `RoomWithSlots` 形式へ正規化変換するロジック |

| `src/components/studio/room-detail-modal.tsx` | UI | 部屋詳細モーダル（常設機材、帖数、個人練習料金、予約リンク/電話発信） |
| `src/config/native-ads.ts` | 設定 | ネイティブPR広告の4大テーマ定義（タイトル、特徴、CTA、アクセントカラー、エバーグリーンURL） |

| `.env.local` | 設定 (秘匿) | Supabase接続設定（`NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`）およびノア認証情報 |
